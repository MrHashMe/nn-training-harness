# Census: systems in which an agent runs ML experiments by itself, compared with the harness

Date: 12 November 2026. Web only; nothing installed or run. About 26 pages read (repository pages, raw source files, GitHub API metadata, two papers, docs). Status words: "read" = opened at its primary source today; "earlier note" = taken from `docs/upgrade/scout/draft/loop-autoresearch.md` (checked 10-11 Nov 2026), not re-opened; "not opened" = not read at source.

Method: searched for current leaderboards and successors, took the official MLE-bench leaderboard (openai/mle-bench) as the evidence anchor, picked the six with the best mix of benchmark evidence with seeds, adoption and maintenance, then read the README and the search/scoring code or the paper. The GitHub pages do not show commit dates; "pushed" below comes from the GitHub API field `pushed_at`. None of the six repositories has a tagged release with a date except where stated.

Seed counts are not listed per entry; the repository recommends at least 3. Five tasks have leaking test data and the maintainers have not fixed v1. Medal rates measure Kaggle-competition solving from scratch, a different job from the harness's (improving a given training repository under a frozen evaluator).

## Shared by two or more strong systems and missing in the harness

1. A repair step for crashed or broken candidates (debug operator with a depth or attempt limit): AIDE (`debug_prob`, `max_debug_depth`, read in `agent.py`), AIRA-dojo (debug limit 10 nodes or 12 h), MLEvolve (`debug_agent`), RD-Agent (`coder_max_loop` 10, `runner_max_loop` 3, `consecutive_errors` 5). The harness lets a session propose one change and revert on failure; whether a crash gets a repair attempt is not stated in the brief ("?").
2. Combining two good candidates (crossover/fusion): AIRA-dojo (crossover operator), MLEvolve (fusion, aggregation across branches), RD-Agent (trace merge at `merge_hours`). The harness search is greedy on one branch and has no compose operator.
3. Parallel evaluation, several workers: AIRA-dojo, MLEvolve, RD-Agent, SkyPilot's autoresearch run (earlier note: about 9x faster wall clock to the same loss on 16 GPUs, simulated sequential baseline). The harness has optional remote GPU runs but the brief does not say it runs panel seeds or candidates concurrently.
4. Branching or non-greedy search (tree, graph, trace): AIDE, AIRA-dojo, MLEvolve, RD-Agent, AIBuildAI. Evidence that it helps is weak (see below), so this is shared but not shown to matter.
5. Memory of earlier attempts retrieved by similarity: MLEvolve (BM25 + FAISS), AIBuildAI (`memorize`), Arbor (not among the six). The harness gives the next session a short history; there is no retrieval across campaigns ("?").
6. A cheap pre-execution check of generated code (code review, leakage check): MLEvolve, RD-Agent debug-run-first. The harness has the transcript scan after the fact and a frozen evaluator, but no stated static check of the proposed diff.
7. Run viewers: RD-Agent (Streamlit, Flask), AIDE (tree visualisation, not verified). Harness has `curve` and `status`, no dashboard.

Not shared (so not a gap by this rule): web or literature scouting (only the harness and, outside the six, MLE-STAR and Arbor do it), seed-panel acceptance, money and token budgets, hidden validation, cost tracking.

## Jobs another system does better, with the evidence

- Operators beat a thin scaffold at equal search policy. AIRA-dojo, Lite: AIRA greedy 45.5% vs AIDE greedy 39.8% (14% relative) with the same policy, only operators differing; AIRA operators use about 2x the completion tokens (arXiv 2507.02554, read). Caveat: crossover and changed memory scoping come together, so the gain is not attributed to crossover alone.
- Search policy gains are small. AIRA: MCTS and evolutionary with the stronger operators add about 2.2 points of gold rate (o3); policy ablation with AIDE operators "only marginal". The Apple/EPFL study (earlier note, arXiv 2609.40303) finds no significant difference among Chain, Greedy, UCB1 and Best-of-N. Conclusion: do not replace the greedy search on this evidence.
- Wall-clock through parallelism: SkyPilot (earlier note) about 910 experiments in 8 h on 16 GPUs; parallel factorial waves reached the same loss about 9x faster than the simulated sequential run. No noise estimate in that post, so the speed-up is real but the quality of the accepted changes is not shown.
- Selecting among several final candidates: AIRA reports that the top 3 validation-ranked submissions add about 10% performance and that choosing by validation closes more than 60% of the gap to choosing by test for greedy agents. The harness confirms only the kept commit versus the start commit.
- Memory: AIRA's own ablation shows memory made almost no difference for AIDE operators; MLEvolve has no ablation. So retrieval memory is unproven. Stateless agents with harness-owned state matched baselines with 84% fewer tokens (earlier note, arXiv 2610.07625), which supports the harness's design rather than a replacement.
- Leaderboard strength: MLEvolve 65.3 +/- 0.8 SEM (3 seeds) against RD-Agent 35.1 +/- 0.4 at the same 12 h (README tables, MLEvolve page). The comparison is the project's own and its README gives no ablation of which component produced the gap. Different job from the harness, so no component can be assumed to transfer.
- Resume from an inner step: RD-Agent resumes from a session log path (e.g. `__session__/1/0_propose`) with an option to clear later logs. The harness resumes runs; resume of a campaign at an arbitrary iteration is "?".

## Where the harness is stricter

- Keep/revert is decided by harness code that runs the frozen evaluator on a split the agent cannot read. AIDE lets an LLM reviewer extract the metric from output; MLEvolve and AIRA-dojo take the number printed by agent-written code; autoresearch lets the agent parse its own log.
- Noise-aware acceptance (fixed seed panel, margin from pooled SD, early discard, confirmation retrain on fresh seeds). None of the six uses repeats inside the loop; their seed repeats exist only to report the benchmark score. (The Prime Intellect speedrun harness and Arbor, outside the six, are the nearest: fixed seeds with a margin, and a held-out margin.)
- Immutability and tamper detection: checksums of evaluator and data every iteration, evaluator self-test, transcript scan, tool allow-list with no shell, fresh worktree. MLEvolve runs candidate code in a plain subprocess with name-based file separation only; AIDE and autoresearch have no equivalent.
- Budgets in money, GPU-hours and agent tokens; none of the six caps tokens or money (AIBuildAI caps agent calls, AIRA wall clock).
- Single-use test evaluation with a hash-chained receipt; the benchmark systems rely on a grader outside the run, which fits a competition but not a repository whose owner is the agent's user.
- Caveat for fairness: the harness has no published benchmark with seeds or intervals ("?"); the six report medal rates on a different task family.
